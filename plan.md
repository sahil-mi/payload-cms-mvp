
Build a modern, visually impressive MVP website using **Next.js + Payload CMS + PostgreSQL**.

The goal is to demonstrate Payload CMS capabilities while keeping the frontend architecture simple, reusable, and component-based.

### Design direction

Create a premium modern creative/technology website — **not a generic CMS/admin demo**.

Use:

- Strong modern typography
- Warm/off-white background
- Near-black text
- Bold accent colors such as violet, lime, coral, and cyan
- Large editorial-style headings
- Generous whitespace
- Rounded cards
- Subtle gradients
- Interesting image treatments
- Soft borders
- Subtle hover animations and transitions
- Excellent responsive design
- Mobile-first layout

The design should feel polished and memorable even though the underlying components are simple.

Do not over-design the UI. Prioritize strong typography, spacing, composition, color, and consistency.

### Frontend

Use reusable components/blocks:

- Header
- Footer
- Hero
- Rich Text
- Image
- Image + Text
- Feature Grid
- Feature Card
- Stats
- Logo Cloud
- Testimonials
- CTA
- FAQ
- Gallery
- Pricing
- Blog Grid
- Project Grid
- Spacer
- Newsletter/Form section

Create a flexible page builder where Payload editors can arrange these blocks to create pages.

### Payload CMS

Use Payload CMS extensively so the MVP demonstrates its major features.

Create collections:

- Pages
- Posts
- Projects
- Authors
- Categories
- Media
- Users
- Forms
- Redirects

Create globals:

- Header
- Footer
- Site Settings

Demonstrate:

- Blocks
- Rich text / Lexical
- Relationships
- Uploads and image handling
- Media library
- Localization
- Draft / Publish
- Revisions
- Scheduled publishing
- Live Preview
- Access control
- User roles
- Hooks
- SEO fields
- Redirects
- Form Builder
- Global configuration
- Validation
- Custom admin fields where useful

### Pages collection

Create a flexible layout builder:

Page

- title
- slug
- SEO
- hero
- layout blocks
- publishedAt
- status

The `layout` field should support reusable blocks such as:

Hero\
FeatureGrid\
ImageText\
RichText\
Stats\
Testimonials\
LogoCloud\
Gallery\
FAQ\
CTA\
BlogGrid\
ProjectGrid\
Spacer

### Content

Populate the CMS with realistic demo content.

Do not use lorem ipsum.

Create:

- A compelling homepage
- About page
- Services page
- Work/Projects page
- Blog/Insights page
- Contact page
- Several individual project pages
- Several blog posts

Use realistic headlines, descriptions, statistics, testimonials, and project content.

### Homepage

Create a visually strong homepage containing approximately:

1. Minimal navigation
2. Large hero section with bold headline
3. Short supporting text and CTA
4. Featured work/project cards
5. Statistics section
6. Services/features grid
7. Editorial image + text section
8. Testimonials
9. Blog/Insights cards
10. Large final CTA
11. Footer

The homepage should feel like a real premium website rather than a technical demonstration.

### Architecture

Keep the code clean and maintainable.

Use:

- TypeScript
- Server Components wherever appropriate
- Client Components only when interaction requires them
- Reusable UI components
- Reusable Payload blocks
- Strong TypeScript types
- Clean folder structure
- No unnecessary abstraction
- No duplicated components
- No hardcoded CMS content in the frontend when it should come from Payload

Keep the MVP reasonably small. Do not build unnecessary functionality.

### Media

Use Payload's Media collection for all website images.

Support:

- Alt text
- Responsive image sizes
- Focal point
- Proper image optimization
- Reusable media relationships

Use Next.js image optimization appropriately.

### SEO

Implement basic production-ready SEO:

- Page title
- Meta description
- Open Graph image
- Canonical URL
- Sitemap
- Robots
- Structured metadata where appropriate

SEO fields should be manageable from Payload.

### Responsive design

The website must work well at:

- 375px
- 768px
- 1024px
- 1440px+

Pay particular attention to mobile typography, spacing, navigation, cards, and image cropping.

### Motion

Use subtle animations only:

- Fade/slide entrance
- Card hover
- Image hover
- Button interaction
- Smooth transitions

Avoid excessive animations.

### Important

Do not invent unnecessary UI patterns.

Keep the design system consistent across every page.

Build the website **component-first**, with Payload as the source of truth for content.
